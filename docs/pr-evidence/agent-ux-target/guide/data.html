Data

Three core relationships hold Agent identity without copying Flow’s existing facts.

The readable model is source revision, catalog selection, and chat binding. Under the first label are two immutable persistence tables: a package snapshot and its compiled definition revision. Existing threads, Works, turns, journal, and receipt remain their own authorities.

Source, future selection, and past binding each change at a different rate

Required addition

1. Immutable source revision

agent_package_revisions stores exportable Mars source. agent_definition_revisions stores each compiled Agent within it. The definition revision UUID and digest are the execution identity.

2. Catalog entry for future chats

agent_catalog_entries selects one immutable definition revision for a personal or system logical Agent. Save moves this pointer. Delete sets removed_at.

3. Immutable chat binding

thread_agent_bindings pins a thread to the exact definition revision used at first Send. Changing Agent means a new thread, not a setter.

Computed policy is not a table

Availability and EffectiveToolPolicy resolve per query or turn from definition and host authority. No permissions cache becomes a second source of truth.

The underlying records are append-only where behavior must remain reproducible

Digest and source implications

Definition digest is SHA-256 over meridian.agent-definition.v1\0 plus canonical normalized JSON. Package digest uses meridian.agent-package.v1\0 plus canonical supported source tree. Timestamps never enter a digest.

First Send transaction

Inside one Drizzle transaction: thread, primary thread_works, thread binding, first writer turn, and existing initial journal evidence. Model execution begins only after commit.

A catalog entry is reusable across Projects, but Project authorization is still checked at launch. Work is context, not catalog ownership or an Agent grant.

Child persistence arrives only with actual delegation

Later extension

After root v1 proves one bound Agent, add exact agent_definition_child_edges resolved at installation and agent_run_tree_budgets for root depth, concurrency, credits, and deadline. Reuse existing thread and turn lifecycle. Do not add agent_runs, agent_run_events, or durable action requests merely for child Agents.

The cutover removes mutable and duplicate identity structures

Deleted behavior

Remove mutable definition rows, editable overlays, slug-based thread binding, a synthetic General fallback, active-package behavior pointers, prompt snapshots treated as identity, compatibility caches, approval grants for native writing, and registry or update records. V3 has no real user data, so replacement is a clean schema cutover, not a compatibility migration.
