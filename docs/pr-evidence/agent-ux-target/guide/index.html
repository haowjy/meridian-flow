How evidence is labelled

The answer

A portable collaborator, not another workflow product.

A writer chooses a named Agent in New Chat. First Send atomically binds that exact definition and Work to a normal chat. The turn uses the existing transcript, activity, edit receipt, and Undo. The normal chat UI stays quiet because a run is a turn, not a second product surface.

The design in one minute

Required addition

Source stays portable

Mars YAML and Markdown define the collaborator. Flow compiles a strict versioned subset, then stores immutable revisions. It does not invent another Agent dialect.

Choice happens once

New Chat owns Agent selection and conditional Work selection. First Send writes the thread, Work link, exact binding, writer turn, and journal evidence together.

Execution remains ordinary

One server preparation path resolves the bound definition, context, model request, and effective tools. Assistant prose leads. An existing receipt appears only when documents change.

Management does not launch

Agents is a workshop for inventory, edit, import, export, and deletion. An existing chat shows the bound Agent as one quiet fact and never switches it.

Normal chat remains quiet because existing authorities already explain the outcome

Existing pattern

Flow already has a turn lifecycle, activity treatment, Yjs edit path, change receipt, and Undo. Root Agent v1 joins those mechanisms instead of duplicating them with run status, generic receipts, or a task center.

What is deliberately absent is part of the design

Deleted behavior

Prior generic receipt rows were proposals, not current Flow

Deleted behavior

Sources and effects, Helpers consulted, and Run details are not a baseline to preserve. They are removed from the target. A normal no-edit answer is assistant prose. An edited answer gets exactly the existing TurnEditsReceipt and Undo.

No parallel run product

No run rail, task center, background tray, workflow engine, run journal, or generic action request system.

No duplicate launch surface

No Agent switch in an existing chat, Home launch cards, package launch pages, test actions, or gallery patterns.

No normal-state ceremony

No routine Ready, Compatible, Preparing, or Completed badges. Exceptions appear at the blocked action.

No premature distribution

No registry, signing, ratings, automatic update, external effects, credentials, or approval gates in root Agent v1.

Implement in proof order, not interface order

Required addition

Prove the root walking skeleton

Mars files to immutable revision to New Chat binding to model event to Yjs edit to receipt and Undo.

Prove that policy is truthful

Read-only Agents cannot see or dispatch edit operations, including fabricated calls.

Add management and local exchange

Create, edit, import, export, delete from catalog, and re-import without altering an existing chat.

Cut over the experience

Keep selection only in New Chat, reuse existing activity and receipt grammar, then delete old paths.
