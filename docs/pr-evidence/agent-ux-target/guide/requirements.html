Requirements

Root Agent v1 must make one useful collaborator trustworthy.

The first useful system lets a writer define or import a named collaborator, choose it in New Chat, and receive an ordinary conversational result. If it edits, the existing receipt and Undo explain and recover the change.

Nine terms prevent the system from becoming a persona, package, and run system at once

Correctness gates must prove authority, identity, recovery, and restraint

Required addition

One semantic authority

Mars owns portable profile semantics. Flow implements a pinned strict subset. There is no permissive partial parser or Flow-specific source schema.

Immutable and deterministic

Canonical compiled JSON and digests are byte-stable. Threads bind revision IDs, never names, slugs, or mutable activation pointers.

Atomic and least-authority

First Send is one Postgres transaction. Source requests actions but cannot grant Project access, choose Work, bind credentials, or broaden host policy.

Accessible and bounded

Selection and authoring work with keyboard and named states at 390 px. Catalog queries stay bounded. First event overhead is at most 10% p95 over the current path.

Quality-gate checklist

Shared positive and negative Mars fixtures compile identically. One hundred repeated compiles keep the same digest. Database failures at every First Send write roll back the aggregate. A fabricated edit against a read-only Agent reaches neither handler nor Yjs. A same-machine 30-run comparison measures first-event latency. Browser probes cover keyboard flow and 390 px overflow.

Runtime and observability restraint

Use the existing turn journal and EventSink. Diagnostics remain internal. Add no runtime library, workflow engine, state machine, event-sourcing layer, run journal, or general capability framework.

The first release intentionally does not solve distribution, background work, or external effects

Deleted behavior

No registry, signing, ratings, automatic update, external effects, credentials, or approvals. No generic evidence disclosures, generic acknowledgements, task center, background controls, gallery badges, search before scale, or a second run/event/action-request system.

These are not hidden scaffolding. The removal inventory names the mechanisms to delete; the delivery plan names the seams that keep later work possible.
