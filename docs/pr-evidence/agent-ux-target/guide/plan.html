Delivery plan

Prove one root-Agent writer outcome before adding delegation or distribution.

The walk begins with a portable strict Mars contract, then traverses definition, binding, policy, model turn, Yjs edit, receipt, and Undo. Management and the final UI cutover arrive after that proof. Child Agents come after root v1. Remote distribution comes later still.

The delivery sequence is a series of evidence gates, not independent feature releases

Required addition

0. Publish the strict Mars subset

Define normalized package and definition contracts, semantic document.read and document.edit actions, deterministic standalone wrapping, canonical digests, and shared fixtures. Flow compiles with existing parsers behind the port.

Gate: byte-identical canonical results, source-located diagnostics, identical digest after 100 compiles, no Flow runtime field in Mars source.

1. Prove the root walking skeleton

Replace persistence with the revision, catalog, and binding model. Seed an edit-capable Writer. Create First Send, prepare Agent turns, pass through existing gateway, Yjs, receipt, and Undo.

Gate: Portless probe proves Mars files to selection to atomic binding to stream to live edit to receipt to Undo, plus Postgres failure injection proves no partial aggregate.

2. Prove truthful policy differentiation

Add a read-only Critic. Use one EffectiveToolPolicy for catalog availability, model advertisement, and dispatch. Reject unavailable, unknown, non-user-invocable, and wrong-Project direct selection.

Gate: Writer sees and dispatches read/edit. Critic sees read only. A fabricated Critic edit hits neither handler nor Yjs.

3. Add management and local exchange

Add flat Agent management, four-field create/edit, immutable save, local import review and export, and soft catalog removal. Keep source/revision facts behind Advanced or More.

Gate: create, edit, export, delete, and re-import work end to end. Editing changes a new chat, never an existing chat. Invalid import persists no partial package.

4. Finish experience and cut over atomically

Keep selection only in New Chat, hide single-Work control, show bound identity once, reuse activity and receipt, and remove old launch and runtime paths.

Gate: experience acceptance, negative source search, pnpm check, pnpm test:db, and real Portless root workflow all pass.

The cutover refuses dual paths and new dependencies

Required addition

Walking skeleton first

Do not build broad UI or extensibility before a root edit reaches receipt and Undo.

Contract tests before consumers

Lock normalization and negative cases before persistence and runtime depend on them.

Atomic cutover

Phases 0 through 4 are one non-deployable lane. No state has both slug or prompt-bake and revision or preparation behavior.

Existing stack only

React, TanStack, Radix wrappers, tokens, Zod, yaml, smol-toml, Drizzle, Postgres, TipTap, Yjs, Vitest, Playwright, Portless, pnpm, Nx, Biome.

Child Agents follow the shipped root path; remote distribution follows local deterministic exchange

Deleted behavior

Do not start management UI before a root edit reaches receipt and Undo. Do not add capability categories before read/edit is truthful end to end. Do not add child semantics before root v1 ships. Do not add remote distribution before local Mars round-trip is deterministic. Do not add background work before a foreground workflow proves why it fails. Do not merge a dual legacy/new execution path.
